# design-dna.md — Krishna Khong Portfolio (SWE-Focused)

## What it is

A fast, zero-dependency static portfolio for Krishna Khong (UNSW Computer Science student), built for engineering hiring managers and technical leads evaluating graduate software and systems candidates.

## Uses that dominate

1. **Assess engineering credibility in 15 seconds**: scan core stack, architecture depth, live demos, and test discipline across `Relay Desk`, `EPI Trainer`, `ai-eval-checker`, and `netregister`.
2. **Inspect proof & contact**: jump straight to GitHub repositories, live demos, or `krishna@khong.dev` on both desktop and 320px mobile.
3. **Read background & legal pages**: experience timeline, education, and Discord bot ToS/Privacy pages.

## This product is

- **Technical** — leads with systems, databases, state machines, and automated testing.
- **Quiet** — lets typography, code/architecture proof, and spacing do the work.
- **Honest** — no inflated metrics, no fake star ratings, no buzzwords.
- **High-contrast** — effortless to read in both light and dark environments.
- **Fast** — zero runtime JS bloat, instant navigation on 320px mobile and 1280px desktop.

## This product is not

- **Playful** — no cartoon avatars, floating emojis, or bouncy gimmicks.
- **SaaS-template** — no generic purple-neon gradients, fake testimonial carousels, or hero stock illustrations.
- **Retail-first** — customer operations support the engineering story rather than overshadowing it.

## Non-negotiables

- Contrast: body text >= 7:1, muted >= 4.5:1, label-on-accent >= 4.5:1.
- Every interactive element has default / hover / focus-visible states.
- 320px wide is a first-class width with working section navigation.
- Copy is real sentences derived from `~/Projects/career-ops/cv.md` and public repos.
- Architecture and project previews show real system structure (state transitions, schemas, CLI output, or live UI captures).

## Reference points (and what to take from each)

| reference | take | do not take |
|---|---|---|
| Linear / Stripe engineering docs | crisp metadata rails, clear hierarchy, technical authority | heavy JS bundles or marketing fluff |
| Editorial technical monographs | restrained typography, generous reading measure | purely text-only walls with no visual proof |
